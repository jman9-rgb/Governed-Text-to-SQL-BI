# Problems faced and how they were solved

| # | Problem | Cause | Fix | Where |
|---|---|---|---|---|
| 1 | Gold views and the golden-question validator were very slow | Gold views re-ran the Silver joins on every query | Gold was turned into indexed physical tables, loaded once with `EXEC gold.sp_load_gold;` (re-run after Silver changes) | `sql/build/06_gold_star_schema.sql` |
| 2 | Questions #3 and #19 timed out (HYT00) | `AUTO_CLOSE ON`: the database shut down when idle and had to restart | `ALTER DATABASE DataWarehouse SET AUTO_CLOSE OFF;` | `sql/build/01_create_database.sql`, `sql/build/22_improvements.sql` |
| 3 | Month-over-month growth included the partial latest month (38 rows, expected 37) | The data ends mid-month | Metric time rule and glossary text: leave out the latest partial month | `sql/build/22_improvements.sql` |
| 4 | January growth returned NULL (#11) | LAG was calculated after the year filter, so the previous month was gone | Metric time rule and prompt rule 14: compute LAG over all months first, filter outside | `sql/build/22_improvements.sql`, `app/genbi_app.py` |
| 5 | Average selling price per category returned 130 rows (#41) | The product agent had no trusted price metric and grouped by product | New weighted-price metric on `vw_product_metrics`; prompt rules 6 and 13 | `sql/build/22_improvements.sql` |
| 6 | Average order value of VIP customers lost the cents (#25) | `total_sales` is bigint and `total_orders` is int: integer division | New trusted metric with an explicit decimal cast on `vw_customer_metrics` | `sql/build/22_improvements.sql` |
| 7 | The AI answered where it should have asked (#29, #42) | The glossary text allowed a default answer for "inactive" | Glossary entries made Clarify-only | `sql/build/22_improvements.sql` |
| 8 | Top 10 customers by sales ranked a merged person first (#22) | Two different customers are both named "Jordan Turner"; the AI grouped by name | Catalog rule on `customer_name`: names are not unique, use `customer_key` | `sql/build/22_improvements.sql` |
| 9 | A correct answer was scored wrong (#12) | `FOR JSON` leaves out NULLs, so the first row of the answer key had one column fewer | The scorer rebuilds every answer-key row with the same columns; a self-test covers it | `app/genbi_eval.py` |
| 10 | A resumed evaluation ignored the agent filter and reused cached answers (run 5 scored 100%) | `--run-id` resumes every unfinished question and uses the cache | Run 5 was excluded from the results. For a clean test, start a new run with `--label ... --agent ... --fresh` | `docs/commands.md` |
| 11 | Free-tier limit on Gemini calls | Hard daily quota | Daily call budget, answer cache and a usage ledger in SQL Server | `sql/build/17_cost_guardrails.sql` |
| 12 | Power BI built wrong relationships and date hierarchies | Auto-detected relationships; date hierarchy used as axis | Rebuilt as single-direction many-to-one, plain date columns, calendar capped at today | `powerbi/powerbi_build_guide.md` |
| 13 | Percentages showed as 8696.00% in Power BI | Measure was already multiplied by 100 | Percent measures return a fraction and use the Percentage format | `powerbi/powerbi_build_guide.md` |
| 14 | Semantic views `vw_customer_metrics` and `vw_product_metrics` failed to build | `gold.report_customers` and `gold.report_products` had been filed as optional analysis instead of build steps | They are now build step 07, before the semantic views (step 08); a script checks that every object is created before it is used | `sql/build/07_gold_reports.sql` |
| 15 | A test passed or failed depending on whether the reader user existed (V13) | The read-only user `genbi_reader` is created in optional step 09, which runs after the step 08 test | The reader-permission test moved to its own file `t09_reader_login_tests.sql`, which says it needs step 09 | `sql/tests/t09_reader_login_tests.sql` |
| 16 | A script broke in the middle of a line when a block was cut out | The cutting script looked for the text `GO` and matched it inside the word `GOOD` | Batch separators are matched only on a line of their own; every file is checked for unclosed quotes and unbalanced BEGIN/END before packaging | packaging checks |
| 17 | Many tests showed differences on a fresh database | Tests compared numbers by eye against `Expected` comments written for the author's data and history | Every test prints PASS / FAIL and has a kind: RULE (always true), SEED (true after its own step) or DATA (depends on your files, shows DIFF) | `sql/tests/*` |
| 18 | The evaluation would have run 0 questions on a clean rebuild | The 46 golden questions are created as `Draft` and nothing ever approved them (the author had approved them by hand) | Step 15 approves every active question whose trusted SQL ran or that needs no SQL; test `t15` A7 checks it | `sql/build/15_build_answer_key.sql` |
| 19 | The evaluation test failed with `Cannot insert NULL into golden_id` | The test picked 3 approved questions; with none approved the ids were NULL | The test uses any 3 active questions and stops with a clear message when there are fewer than 3 | `sql/tests/t20_evaluation_tests.sql` |
| 20 | Test I8 failed although the glossary was correct | The test looked up the glossary line under the term; the prompt view names that line after the metric code | The test looks under `avg_selling_price_weighted` and checks the term inside the line | `sql/tests/t22_improvement_tests.sql` |
| 21 | A failed test showed only `At least one RULE test failed` | The failing rows were far above the end of the output | Each test file prints a `FAILED RULE TEST` table right before the error | `sql/tests/*` |
| 22 | Eleven versions of the app and the evaluator, one per phase | Each phase was saved as a new file | Only the final version is kept: `genbi_app.py`, `genbi_eval.py`, `genbi_validator.py` | `app/` |
| 23 | Nothing would have told us if a semantic view lost, renamed or retyped a column | The AI, the golden questions and the dashboards all depend on 5 views, and no test compared them with an agreed structure | Step 24 stores a data contract (grain, key, every column and type) and `sp_contract_check` reports any drift; test `t24` proves the check detects a change | `sql/build/24_data_contracts.sql` |
| 24 | Step banners still carried the old phase numbers (for example `PHASE 7` in file 16) | Files were renamed into steps but not their headers | Every banner now shows its step number | `sql/build/*` |
